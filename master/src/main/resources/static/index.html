Mini-K8s

Building a Distributed Container Orchestration Engine from Scratch

Mini-K8s is an educational, production-modeled container orchestration platform inspired by Kubernetes. Featuring a central Spring Boot Master control plane, least-loaded scheduling, reconciliation loops, gRPC networking, and real Docker Engine execution.

☕ Java 21 / 25 🍃 Spring Boot 3.4 ⚡ gRPC / Protobuf 🐳 Docker Java SDK ⌨️ Picocli CLI
01 / System Design

Why Container Orchestration?

The Problem with Monolithic Deployments

  • Manual container placement across servers is error-prone.
  • When a host or process dies, workloads stay dead.
  • No automated horizontal scaling or load balancing.
  • Inconsistent resource allocation (memory spikes crash nodes).

The Mini-K8s Solution

  • Declarative desired state: Tell Master "I want 3 Nginx replicas".
  • Smart Scheduler: Places containers on nodes with sufficient CPU & RAM.
  • Continuous Reconciliation: Replaces dead containers automatically.
  • Zero Docker calls on Master: Clean microservices abstraction.
02 / Control Plane

Master Control Plane Architecture

1. Worker Registry

Thread-safe, in-memory registry of all cluster nodes. Tracks heartbeat timestamps, registration lifecycle, and available resources.

2. Resource Scheduler

Implements ResourceAwareLeastLoadedStrategy. Evaluates available millicores and memory to pick the optimal worker.

3. Replica Manager

The brain of reconciliation. Computes Delta = (Desired - Actual) and triggers idempotent gRPC launch/stop commands.

Key Engineering Highlight: Uses fine-grained per-deployment locking to prevent race conditions during rapid concurrent scale-up/scale-down requests.
03 / Worker Nodes

Worker Node & Docker Engine Integration

gRPC Service (`worker.proto`)

High-performance protobuf-compiled RPC channel for cluster operations:

  • • StartReplica(replica_id, image, resources)
  • • StopReplica(replica_id)
  • • RemoveReplica(replica_id)
  • • GetWorkerStatus()

Docker Java SDK Runtime

Translates RPC requests into real Docker daemon instructions:

  • 🏷️ Idempotent Labels: Containers tagged with minik8s.replica-id for recovery after reboot.
  • ⚖️ Resource Quotas: Maps millicores to Docker CPU quota and bytes to memory limits.
  • 💓 Periodic Heartbeat: Publishes live metrics back to Master every 5 seconds.
04 / Fault Tolerance

Self-Healing & Failover Mechanism

1. Desired State
Stored in ReplicaManager
2. Worker Failure
Heartbeat expires (>15s)
3. Node Eviction
Replicas marked FAILED
4. Auto-Rescheduling
Scheduled to healthy node

When a worker crashes or network partition occurs, the Master's HealthMonitor marks the worker UNAVAILABLE. The ReplicaReconciliationJob detects that actual running replicas is less than desired replicas, and automatically schedules replacement replicas to healthy workers without human intervention.
